# SPACE image-catalog contracts — v1.17.18

These three MathSpecs were frozen before CPU fixtures and GPU implementation. All output words, including statuses, labels, counts and floats, require zero differing bits. Binary32 uses the existing finite-input software RN-even operation contract. No FMA, reassociation, or implicit quantization. Finite overflow is rejected by the reference before GPU submission.

## Background mesh (opcode51)

The supplied rectangular mesh has 2..64 samples per axis. Query (x,y) means index coordinates of the mesh sample centers, not sky coordinates or automatically scaled pixel coordinates. Clip each coordinate to [0,size-1], floor, and retain its RN32 fractional part. The neighboring sample at the upper edge is the same edge sample. Interpolate the two rows along x, then along y. Each lerp separately rounds 1-t, both products and their sum; at t=0 use the canonicalized endpoint directly. Signed zero is canonical positive zero. Missing mesh samples are rejected. Mesh estimation and pixel-to-mesh coordinate conversion remain explicit upstream tasks. This is linear interpolation with nearest-edge extension, not Photutils' default cubic zoom.

## Component graph (opcode52)

Each node represents one already labeled, nonempty, disjoint pixel component. Its nonzero uint32 ID is unique; for tile assembly use the minimum global row-major pixel index plus one. Pixel counts are positive and their total fits uint32. Edges refer to node indices, are undirected, and may repeat or be self-edges. Compute the complete equivalence closure. For every original node emit the minimum ID of its connected component, the sum of all its member counts, and either the minimum ID or0 depending on the global npixels criterion. The Python oracle uses BFS; the GPU uses independent union-find with monotonically decreasing roots. Both process full graphs for each dispatched output record, so record partitioning cannot lose transitive boundary equivalences.

The mosaic adapter takes a rectangular, non-overlapping grid of label tiles, verifies each tile against the canonical connected components of its foreground, and includes every 4/8-neighbor seam, including diagonal corner contacts. Local segmentation must use npixels=1: filtering before seam merging could irreversibly discard real global sources. All-zero mosaics have an explicit empty path; no fake graph node is inserted. The adapter is preprocessing/relabeling on CPU, equivalence closure runs on GPU. A graph holds at most512 local components; larger graphs require a future hierarchical merge contract.

## Source catalog (opcode53)

All arrays share an image shape, at most128x128; at most256 requested unique nonzero source IDs and1,048,576 pixel/source comparisons. Pixels contribute only when valid=1 and label=source_id. Background-subtracted residual d is rounded once. Signed flux includes negative values. Input variance is already total per-pixel variance; summing assumes independent errors and does not account for correlated noise. Morphology uses max(d,0), following Photutils' negative-pixel convention.

First pass in global row-major order accumulates signed flux, variance, positive weight and x/y weighted sums, each with separate RN32 operations. If weight>0, divide to obtain cx,cy; a second pass forms dx,dy and accumulates w*(dx*dx), w*(dx*dy), w*(dy*dy), finally dividing by weight. Products follow those exact parentheses. Output10 words: status,count,flux,variance,positive_flux,cx,cy,mu20,mu11,mu02. Status1 means no valid source pixel, status2 zero positive weight, status0 valid morphology. Unavailable fields are zeros; measured signed flux and variance remain available for status2. No fabricated centroid, WCS, deblending, fitted PSF or posterior.

Independent original code only; no external implementation bundled.

GPU families considered: independent gather; graph union/find versus iterative label propagation; segmented parallel reductions versus ordered reductions. Floating tree reductions change the required RN32 sum order and are excluded. Portable independent-record gather/union-find/ordered reductions admit local sizes32/64/128/256 and packing1/2/4.
