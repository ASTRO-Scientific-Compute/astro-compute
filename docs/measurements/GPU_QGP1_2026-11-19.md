# GPU QGP1 — full scientific output measurements

**Observed output: 16,727,640,608 raw bytes → 5,346,627,188 QGP1 packet bytes on RTX, or 5,346,622,692 on RX 470.** This is the accumulated scientific result size, not model weights or input size. For RTX, original/packet ratio is 3.128634× and packet size reduction is 68.037171%.

Status: GPU lossless packaging verified on the declared workloads. Size reduction is data-dependent. The November 19 automatic application campaign did **not** demonstrate an E2E speedup. Offline CPU archival research is reported [separately](OFFLINE_COMPRESSION_RESEARCH.md).

## Full workload and coverage

Both campaigns below process the same declared scientific workload per full pass:

- PDE: one downloaded corpus containing **10,000 distinct trajectories**, all **201 saved times × 1,024 cells**; 2,058,240,000 result values. No trajectory repetitions within that corpus pass.
- BIO: five supported SBML models, 51 saved times, two species, 128 replicas. Replicas are not new biological models.
- SIGNAL: all 48 MIT-BIH records on the supported first lead; complete declared record processing, not all leads or all possible ECG analyses.
- CHEM: 12 Lennard–Jones combinations, four configurations × three schemes. Reference-problematic SPC/E is excluded.
- SPACE: one adapted Kepler example, with 128 replicas; not 128 distinct orbits or a qualification of the entire source simulator.

The declared output contracts comprise **128 complete output records**, delivered in 64 internal chunks / 69 graph evaluations per pass. Internal chunks are not independent research cases. Repeating the full work does not increase unique-corpus coverage.

## Timing and byte definitions

E2E is the measured full-run wall boundary including execution preparation, integrity handling, computation, transfer, buffered result persistence and worker completion. Offline compilation and the independent inverse/reference audit are excluded. Files may still reside in the OS page cache: no durable `fsync` or WAN delivery time is claimed. CPU is aggregate process-tree CPU-seconds. GPU intervals can overlap with CPU work and, in overlap mode, other GPU intervals; do not sum them into E2E. Backend peak measures backend buffers, not total VRAM or total system memory. See [common definitions](MEASUREMENT_INDEX.md#definitions).

Packet bytes, API transfer bytes and stored DAG bytes are separate measurements. Small metadata and raw fallback must be included. No value labeled as a calculated network payload in a private log is treated here as observed internet traffic.

### Full lossless audit

`FULL_INVERSE_AUDIT.json` records **128 unique raw outputs × six compressed passes = 768 output comparisons**, with **zero differing bytes** after independent decoding. The audit took 1,631.972204 s wall / 1,564.516136 CPU-s and is outside the E2E table. Its cost must be included when considering this particular complete offline verification workflow.

The execution status explicitly says reference validation was not run. This proves lossless preservation of the GPU result bytes; it does not independently certify the underlying scientific mathematics. Separate small codec qualification on all three GPUs does not turn this RTX full timing campaign into a three-GPU timing result.

Both Radeon workers reused 64 measured profiles each. RTX correctly refused reuse after the observed PCIe link identity changed and selected the conservative setting-1 QGP1 fallback. The original controller stopped with `PROFILE_REUSE_NOT_PROVEN:rtx` because it incorrectly expected reuse on every device. The original stop was retained; review accepted the conservative fallback. The 15 completed science sessions were not repeated. Only the three previously unstarted image sessions were subsequently run under a separate continuation budget: 18 sessions total, including the [image measurements](IMAGE_INFERENCE_2026-11-19.md).

**No E2E improvement was established by automatic application.** Writer-queue waits were **96.239 s (RTX), 36.242 s (RX ×8), 2.790 s (RX ×1)**. These waits overlap other work and are not additive E2E components. Shared storage backpressure was observed; it does not prove an SSD, filesystem, TRIM or firmware fault. The data does not isolate PCIe ×1 as the sole source of a slowdown, and no internet throughput was measured.

### Numerical correctness and byte preservation are separate

Every restored output was checked against retained audited output identities. The resulting equality inherits earlier numerical evidence; this campaign did not recompute scientific reference answers. The prior `dispatch_corpus_v1 / 20261119T032516Z` per-device `science-1/OFFLINE_AUDIT.json` chain records these distinct scopes:

- PDE: the full 2,058,240,000-value result compared in the prior reference chain, with maximum absolute error approximately 0.0297906912 and maximum relative L2 error approximately 0.00107073952.
- BIO: five supported models passed their case-specific reference tolerances; this is not all of SBML.
- ECG: 48 records, ±150 ms annotation matching; TP 108,461, FP 672, FN 1,007; sensitivity 99.0801%, positive predictive value 99.3842%. These are scored detector metrics, not ZERO BIT with annotations or a clinical qualification.
- CHEM: all 12 Lennard–Jones combinations passed at the precision of the published NIST references. No claim is made for excluded SPC/E.
- SPACE: the single adapted Kepler orbit was checked against a high-precision analytic reference under position, velocity and energy tolerances; this is not official simulator parity.

Different GPUs need not produce identical floating-point bytes under a tolerance contract. Their slightly different packet sizes are not a lossless failure: ZERO BIT refers to restoring each device's own original bytes.

## Reproduction limits

The evidence above is a public summary of owner-retained primary records. Current engine, codec implementation, learned profiles, datasets and raw result archives are not released here. The public demo cannot reproduce these private full-corpus campaigns. No new physical GPU measurement was performed for this documentation update. No power/energy advantage, sustained network delivery rate or universally optimal codec is established.
