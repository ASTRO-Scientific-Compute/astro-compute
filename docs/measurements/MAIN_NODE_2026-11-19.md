# Main Node measurements — 2026-11-19

These are summaries of private qualification records inspected for this documentation update. They are not new measurements, a public runtime distribution or third-party reproduction. Raw logs, deployment identities and private source remain withheld.

## Campaign A: two-host packet execution

**VERIFIED within this finite local campaign.** Two physical hosts used four persistent workers: BC-250 Vulkan, RTX 4060 Ti CUDA, RX 470 ×8 Vulkan and RX 470 ×1 Vulkan.

The input sets were distinct and deterministic; all used the same three-matrix DAG structure: `[256,1024] × [1024,256]`, followed by multiplication by `[256,128]` and `[128,64]`. This is 12 complete synthetic workloads, not 12 different graph topologies.

| Measure | Result |
|---|---:|
| Complete workloads / unique packet executions | 12 / 36 |
| Dependency edges | 24 |
| New claims while a peer still held unfinished work | 35 |
| Lost / duplicate accepted completions | 0 / 0 |
| Final values checked against independent Float64 | 196,608 |
| Maximum absolute error | 1.13563413e-7 |
| Gateway decoded array bytes | 0 |

Numerical contract: `abs(actual-reference) <= 2e-5 + 5e-4*abs(reference)`. All final values passed. This is **not** ZERO BIT against Float64 or between devices.

QGP1 results and compressed dependencies were forwarded unchanged by the gateway. Downstream workers decoded dependency inputs before GPU upload. Zero gateway decoding does not mean the whole system performs no CPU decoding.

|---|---:|---:|---:|---:|

Work counts differ, workers overlap, and these wall times are not additive. This table is not an equal-work device ranking. Main Node service CPU and network-wide researcher latency are separate boundaries.

A separate compression check restored all 50,331,648 source bytes exactly using an independent decoder. This codec ZERO BIT claim does not replace the numerical DAG check.

**Limits:** trusted local SSH operators and registered graphs; no public-miner authentication, internet deployment or Node A/B failover. This campaign's qualification processes were closed. Its subsequent CPU/SSH fixes were not requalified in a second identical physical campaign. Net CPU savings from Main Node compression were not established.

## Campaign B: later private Core/API integration

A separate, later qualification left a private Core/API service running and closed its finite GPU workers. It passed 47 CPU protocol/state checks, 15 real HTTP/SSH/lifecycle checks, and a 120.184-second availability probe with 61 successful samples. The probe is not a loaded multi-hour test or a machine-reboot test.

Two bounded four-worker campaigns each processed the same 12 complete scientific workloads. Thus 12 distinct scientific input sets plus 12 comparison repeats; 36 science packets and 24 dependency edges per campaign. Every packet output was checked: 1,376,256 values per campaign, maximum absolute error 8.73088091e-7 under the same tolerance above. No science completion was lost or accepted twice.

The BC-250 also served three short prompts on a **separate complete 426,688-parameter model**: two completed 16-token generations and one cancelled generation per campaign. This was sequential conversation service within one resident worker, not concurrent multiuser decode or service of the 124M model.

All 34 initially accepted token receipts and 39 later accepted receipts matched independent Float64 greedy selection. Complete logits were not exported; no full-logit error bound is claimed. After cancellation fencing, no later token was accepted; all conversation state was released. QGP1 framing expanded the tiny token receipts, so compression savings are not claimed for them.

The two campaigns used eight physical sessions in total. The initial campaign recorded overlapping science/AI lease activity; the final one did not. Shared queue integration is demonstrated, but the final campaign alone does not prove simultaneous cross-host GPU arithmetic. A controlled service restart and idempotent receipt resubmission were checked; general machine loss, failover, public identity and multi-hour loaded service remain unqualified.
